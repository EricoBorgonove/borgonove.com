Guia completo - Deploy automático com GitHub Actions + HostGator cPanel (SSH Key)

Objetivo:
- Publicar automaticamente no cPanel sempre que houver push na branch main.
- Usar autenticação por chave SSH (mais segura do que senha).

Arquivos já preparados no projeto:
- .github/workflows/deploy-cpanel-hostgator.yml
- public/.htaccess

------------------------------------------------------------
1) Pré-requisitos
------------------------------------------------------------
- Projeto no GitHub.
- SSH habilitado na HostGator/cPanel.
- Acesso ao cPanel com "Terminal" ou "SSH Access / Manage SSH Keys".
- Branch principal chamada "main" (ou ajuste no workflow).

------------------------------------------------------------
2) Gerar um par de chaves SSH para o deploy
------------------------------------------------------------
No seu computador (terminal):

ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/gha_hostgator_deploy

Isso gera:
- Chave privada: ~/.ssh/gha_hostgator_deploy
- Chave pública: ~/.ssh/gha_hostgator_deploy.pub

Se preferir chave com senha, defina passphrase no comando.
Se não quiser passphrase, pressione Enter em branco.

------------------------------------------------------------
3) Autorizar a chave pública na HostGator (cPanel)
------------------------------------------------------------
Opção A (painel cPanel):
1. Abra "SSH Access" -> "Manage SSH Keys".
2. Importe o conteúdo de ~/.ssh/gha_hostgator_deploy.pub.
3. Clique em "Authorize" para ativar a chave.

Opção B (terminal SSH já habilitado):
1. Conecte no servidor.
2. No home do usuário, edite ~/.ssh/authorized_keys.
3. Cole a chave pública em nova linha.
4. Ajuste permissões:
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys

------------------------------------------------------------
4) Descobrir dados de conexão e pasta alvo
------------------------------------------------------------
Você vai precisar destes valores:
- CPANEL_HOST: host/IP SSH do servidor
- CPANEL_PORT: normalmente 22
- CPANEL_USERNAME: usuário do cPanel/SSH
- CPANEL_TARGET_DIR: pasta publicada
  exemplo comum: /home/SEU_USUARIO/public_html

Observação:
- Em alguns planos, o host SSH pode ser diferente do domínio.

------------------------------------------------------------
5) Cadastrar secrets no GitHub
------------------------------------------------------------
Repositório -> Settings -> Secrets and variables -> Actions -> New repository secret

Crie:
- CPANEL_HOST
- CPANEL_PORT
- CPANEL_USERNAME
- CPANEL_TARGET_DIR
- CPANEL_SSH_PRIVATE_KEY
- CPANEL_SSH_PASSPHRASE (somente se sua chave tiver passphrase)

Como preencher CPANEL_SSH_PRIVATE_KEY:
1. Abra a chave privada local:
   cat ~/.ssh/gha_hostgator_deploy
2. Copie TODO o conteúdo (incluindo BEGIN/END).
3. Cole no secret CPANEL_SSH_PRIVATE_KEY.

------------------------------------------------------------
6) Confirmar o workflow
------------------------------------------------------------
Arquivo: .github/workflows/deploy-cpanel-hostgator.yml

Fluxo atual:
1. checkout
2. npm ci
3. npm run build
4. limpa destino remoto (mantém .well-known)
5. envia dist/* e dist/.htaccess para CPANEL_TARGET_DIR

------------------------------------------------------------
7) Primeiro deploy
------------------------------------------------------------
1. Faça commit e push na main.
2. Abra GitHub -> Actions -> "Deploy cPanel HostGator".
3. Confira o log de execução.
4. Acesse o site e teste rotas diretas:
   /utilidades
   /disciplinas
   /contato

------------------------------------------------------------
8) Troubleshooting rápido
------------------------------------------------------------
Erro de autenticação SSH:
- Verifique usuário, host, porta e autorização da chave no cPanel.
- Confirme que a chave privada no secret está completa.

Erro "permission denied" na pasta alvo:
- Ajuste CPANEL_TARGET_DIR.
- Confirme permissões de escrita do usuário SSH.

Rota React retornando 404:
- Verifique se .htaccess foi publicado em public_html.
- Confirme que mod_rewrite está ativo no Apache.

Deploy funcionou, mas site antigo continua:
- Limpe cache do navegador/CDN.
- Confirme no log que os novos arquivos foram enviados.

------------------------------------------------------------
9) Segurança recomendada
------------------------------------------------------------
- Use uma chave exclusiva só para deploy.
- Se possível, use passphrase na chave (preencher CPANEL_SSH_PASSPHRASE).
- Revogue a chave no cPanel se houver suspeita de comprometimento.
- Evite usar usuário root (use o usuário normal do cPanel).
